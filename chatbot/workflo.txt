# 🤖 Yogateria Chatbot Workflow Architecture

This document provides a deep dive into the chatbot's processing lifecycle, from the moment a user types a message to the final visual response.

## 🌊 Complete Process Flow


## 🔍 Detailed Component Breakdown

### 1. User Interaction & Identification
*   **Auto-Detection**: The backend doesn't just wait for a login. It uses **Regex** to scan every message for identification patterns like `cus_...`, emails, or Brazilian CPF/CNPJ numbers (`server.py:605-612`).
*   **State Management**: For TinyERP users, the system maintains a `conversation_state`. It knows if it's waiting for a user to choose between "Recent Orders" or "Search by Date" (`server.py:657`).

### 2. Context Gathering (The "Brain" of the Bot)
The chatbot uses **Retrieval-Augmented Generation (RAG)** to provide accurate answers:
*   **Catalog Sync**: Every time the server starts, it builds a `product_lookup` cache from `yogateria_products.json` (`server.py:122`).
*   **Pricing Truth**: A `generate_catalog_summary()` function creates a "Category Pricing Overview" (e.g., "Cheapest Yoga Mat is BRL 89.00"). This is injected into the LLM's system prompt so it never hallucinates prices (`chatbot.py:11`).
*   **Order API**: If an order number is detected (e.g., `#1234`), the backend performs a real-time fetch from the `ORDER_API_URL` to get the latest shipping status (`server.py:405`).

### 3. LLM Orchestration (How & Where LLM is Used)
We use a **Hybrid LLM Strategy** for speed and intelligence:
*   **Condensation (Groq)**: The `llama-3.1-8b-instant` model on Groq is used to instantly condense long chat histories into a single, focused search query (`chatbot.py:183`).
*   **Reasoning (OpenRouter)**: The primary LLM (configured in `LLM_MODEL`) takes the condensed query, the retrieved order context, and the product summary to write the final response (`chatbot.py:116`).
*   **Vector Store**: We use **Qdrant** to store and retrieve specific technical details about yoga products (`chatbot.py:133`).

### 4. Product Card Intelligence
Unlike simple bots that only return text, this system "sees" what it has typed:
*   **Keyword Scan**: The server scans the LLM's response. If the LLM mentions "Yoga Mat," the server looks up the image, price, and URL (`server.py:928` appx).
*   **Variant Precision**: If the LLM mentions a color (e.g., "Blue"), the system specifically selects the variant card for the Blue version, including the specific `variant_id` and the correct thumbnail (`server.py:115`).
*   **Dynamic URLs**: URLs are automatically constructed with query parameters (e.g., `?Cor=Azul`) so the user lands on the exact product configuration they discussed (`server.py:229`).

### 5. Data Persistence & Performance
*   **PostgreSQL/SQLite**: Every interaction is logged with a `message_id`. This allows for the **Feedback System** (Thumbs Up/Down) which is stored in separate tables (`GOOD_FEEDBACK`, `BAD_FEEDBACK`) for future fine-tuning (`db.py`).
*   **Async Processing**: The system uses `FastAPI` and `lifespan` handlers to ensure the product cache and LLM connections are ready before the first request hits.
